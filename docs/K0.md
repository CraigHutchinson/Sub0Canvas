# K0: timing the viewer's interactions

Status: **built** (2026-11-24), `tools/k0/`, `test/k0.test.js`, `perf/k0/`. Brief: [sessions/k0-ui-kpis.md](sessions/k0-ui-kpis.md). The budgets are
[AUTHORING.md](AUTHORING.md) section 3.2 (R-AUTH-15); the measured numbers are in that table and summarised in [SCALE.md](SCALE.md) section 6.1.

A local-tier timing check: it needs mains power and a quiet machine and **never runs in CI**. It is not in `ctest --preset quick` or `full`; `ctest --preset timing`
runs it (the test `Sub0Canvas_K0_timing`) beside the C++ benchmarks, and prints a line beginning `SKIP timing` (ctest reports it skipped) on battery, on a busy machine
or without a browser.

```bash
node tools/k0/run.mjs                      # both scopes, 20 repetitions after 2 warm-up; one verdict line, a line per breach
node tools/k0/run.mjs --scope mirror --reps 5 --force    # a quick look (--force: battery or busy machine; recorded as forced, never a baseline)
node tools/k0/run.mjs --record             # a full steady run becomes this host's baseline, perf/k0/<host>.json (commit it with the reason)
node tools/k0/judge.mjs out/k0/last.samples.json --baseline perf/k0/<host>.json    # judge a samples file again, no browser
SUB0MATH_PERF_HOST=dev-host-1 node tools/k0/run.mjs      # the host alias a record is named by (this repository is public: no real host names)
```

Output, in order: `SKIP timing: ...` or

```text
k0: OVER-BUDGET 8 of 20 over budget (p95), 0 regressed vs baseline, 4 not yet possible
BREACH large/folder-toggle: p95 446 ms > 50 ms (p50 386.3, x8.9)
report: out/k0/last.report.md
```

The full table, the machine and the scope sizes are in `out/k0/last.report.md` (ignored by git), the samples in `out/k0/last.samples.json`.

## How it measures

* **Driver**: `tools/k0/cdp.mjs`, a Chrome DevTools Protocol client on Node's built-in `WebSocket` (Node 22 or later). No dependency, no download. The browser is found by
  the pattern `tools/screenshots.mjs` uses (argument, `BROWSER`, Edge or Chrome in the usual places) and started `--headless=new` with a throwaway profile; Edge starts from a
  launcher that exits at once, so the endpoint is read from `<profile>/DevToolsActivePort`. `tools/serve.mjs` serves the page and the bundles on a free port.
* **Scopes**: `mirror` (the synthetic mirror's canvas bundle, [MIRROR.md](MIRROR.md): 49 files, 235 blocks, 8 turns, generated by `tools/mirror`) and `large` (`gen-large.mjs`: a
  deterministic generated subtree of 1,590 files and 20,034 blocks in 159 folders, three turns with every 20th file changing, two layers of 300 and 120 items; texts by id).
* **Scenarios** (`scenarios.mjs`, one per row of `perf/k0/budgets.json`, injected into the page): each clicks a real element (or fires `input` on the filter) and times from the
  input to the next painted frame (a `requestAnimationFrame` callback, then a task: the frame has been presented). Every repetition does work: expand then collapse the largest
  folder; two files; two blocks in different files (list) and two block headers (code); first and last turn; a layer then back to code; `a` then `ab` in the filter. The first
  view is a new tab per repetition, from navigation start to the tree and to the first file painted (a mutation observer installed before the page's scripts).
* **Statistics**: 2 warm-up runs dropped, 20 kept; p50 (median) and **p95 by nearest rank** (the 19th of 20) per interaction; the judge compares p95 with the budget. The idle
  frame (timing an action that does nothing) is recorded per scope: it is the floor, about 16.5 ms here, so a number near it means the interaction cost nothing measurable.
* **Not yet possible, reported as such**: an event from another actor while reading (V1a), and a file opened with its text fetched (content on demand, R-AUTH-14: a bundle holds
  every text, so every open is "cached").
* **Record**: host alias, machine (system, arch, CPU model), power state (mains or battery, CPU busy fraction before the run, forced or not), browser and version, Node, commit,
  repetitions, scope sizes (files, blocks, turns, bundle bytes, DOM nodes), every sample. A private repository would be recorded by scope size only (AGENTS.md).

## The judge and the baseline

The verdict is deterministic from the samples file, the budgets and the baseline (`judge.mjs`, tested without a browser). `OVER-BUDGET` says the viewer is not yet within a budget:
a target, and with the design not yet built (V1a) expected, so it does **not** fail the run (`--strict` makes it). `FAIL` is a **regression against the baseline** (p95 more than
25% and 2 ms worse than this host's recorded p95; `perf/k0/budgets.json` holds the tolerance) or a row that should have samples and has none. This matches sub0perf: a
regression against the recorded baseline blocks, and a baseline is changed deliberately, with a reason, and committed with the change that moved it.

## Proposal: a shared samples import for sub0perf (for Sub0Math, S-M9, not implemented there)

K0 is a Node benchmark outside Sub0Math's native-executable model, so it writes its own samples file and judges it itself. The family loop (one verdict line, `accept`, the
logged `accepted` list, the pre-push gate, the power refusal) should apply to any tool that can produce wall-clock samples. The proposal is a generic import with a fixed format,
`sub0perf-samples-1`; K0's `k0-samples-1` is the same shape with fewer fields and would be renamed on adoption.

**File** (JSON, written atomically, one per run):

```json
{"format": "sub0perf-samples-1", "tool": "k0", "unit": "ms",
 "host": "dev-host-1", "machine": {...}, "power": {"state": "ac", "forced": false, "busyCpu": 0.1}, "commit": "d9f33f6", "recorded": "2026-11-24T02:04:02Z",
 "environment": {"browser": {"name": "msedge", "version": "Edg/159.0.4402.13"}, "node": "v24.22.0"},
 "repetitions": 20, "warmup": 2,
 "benchmarks": {"<scope>/<name>": {"unit": "ms", "samples": [18.7, 19.0], "budget": {"p": 95, "limit": 50}, "noise": {"idle": 16.5}}}}
```

**Rules**: samples are raw values in one unit per file, in measurement order, warm-up already dropped (the count and the dropped number are in the header); `power` is the
state at the time of measurement and `forced: true` makes the record unusable as a baseline; a benchmark may carry a `budget` (`p` and `limit`: an absolute target in the
same unit, independent of any baseline) and a `noise.idle` floor; names are unique and may use `/` for grouping; a benchmark that cannot be measured yet is present with
`"samples": []` and `"notYetPossible": "<reason>"`, which the judge reports and never fails.

**Commands** (additions to `bench_check.py`, reusing `power`, `stats`, `accept` and `baseline` as they are):

| command | does |
|---|---|
| `import-samples --samples FILE [--baseline FILE]` | validates the format, judges by the existing rules (robust CV and the baseline tolerance, bimodal detection when 5 or more samples), applies each `budget` as a second, absolute check, prints the one verdict line (`perf: PASS|OVER-BUDGET|FAIL ...`) and a line per row beyond noise or over budget, writes `X.report.md`, exit 0, 1, 2 as today |
| `baseline --results FILE` and `accept --results FILE ...` | work on an imported file unchanged (`power` refusals, the `accepted` log, `--reason`); the baseline stores p50 and p95 per benchmark where the native format stores a calibrated median |
| `gate --samples FILE` | the pre-push stanza for a non-native tool: judge a fresh samples file against the committed baseline |

**Differences from the native format that the judge must honour**: no calibration kernel scaling (the unit is the tool's own; the `noise.idle` floor and the power state stand in
for it); the statistic compared is a high percentile (p95, nearest rank) because the budgets are tail budgets, not the median; an absolute `budget` is judged beside the baseline,
so a tool can be over budget and still not regressed (`OVER-BUDGET`, exit 0 unless `--strict`); and one samples file may hold several scopes. **Done means** for Sub0Math: a unit
test with a synthetic samples file for each verdict, `accept` refusing a forced or battery record, and K0 switched to `import-samples` with its judge deleted.

## Findings (2026-11-24, first run)

All eight failing interactions on the large subtree cost the same 380-460 ms at p50: each click runs `render()`, which rebuilds the tree (the structure of all 1,590 paths, though only
open folders get rows), the code pane and the block list of every block in the document (20,034 rows, most of the 60,896 DOM nodes), whatever the click was for (read from
`src/view.js`, not profiled: a profile of the render is the first step of V1a). There is
no interaction-specific cost to fix: the budgets need the V1a design (AUTHORING.md section 3.1: patch what changed, windowed lists, a scoped block list), and the order follows
the ratios above. The filter keystroke shows it most clearly: the render is skipped (`fill` replaces only the list), yet matching every block rebuilds 20,034 rows in 223 ms at p95.

**What V1a must fix**: (1) never rebuild the block list on a selection, a turn or a layer switch (selection patches one class; the list is scoped to the open file or folder and
windowed); (2) the tree renders open folders only, windowed, and a folder toggle patches its own rows; (3) the code pane is kept across a layer switch and a turn switch applies a
delta; (4) a filter's results are windowed (a page of matches). Done when `node tools/k0/run.mjs` reports `PASS` on the large scope, then the baseline is re-recorded with `--record`.
