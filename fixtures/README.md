# Fixtures

Test data, one directory per kind. Each kind says where it comes from, which test keeps it honest, and how it is refreshed. A generated
fixture is never edited by hand: change its generator and regenerate (`npm run fixtures` refreshes both generated kinds).

| directory | what it is | origin | checked by | refresh |
|---|---|---|---|---|
| [demo/](demo/) and `demo.js` | the viewer's demo story: one attempt in four turns, every identity event and a 1-N issue; `demo.js` is the same files bundled for `index.html` (a page opened from `file://` cannot fetch) | generated by `tools/gen-fixtures.mjs` | `test/fixtures.test.js` (regeneration is byte-identical), `test/model.test.js` | `npm run fixtures:demo` |
| [git/tinycalc/](git/tinycalc/) | captured git plumbing output of an invented 200-commit repository (log, path-limited logs, texts, trees, a shallow clone's log), the input of `test_revision_index` (R-SRC-8) | generated by `tools/git-fixture.mjs capture` (a real local repository built from the plan in that file; byte-identical on every run) | `test/history.test.js` (regeneration is byte-identical), `test_revision_index` | `node tools/git-fixture.mjs capture` |
| [scenarios/g1-tinycalc/](scenarios/g1-tinycalc/truth.json) | the hand-checked identity history of five functions across that repository, seven scenarios (directory, earlier revision, single paths with renames, a merge, a window, a shallow clone) | hand-written from the plan, checked against `git log -L` and the diffs (the `how` field) | `test_revision_index` (captured output), `test/history.test.js` (live git) | by hand, with the plan |
| [golden/](golden/README.md) | real producer output: three Sub0Squad attempt directories, frozen | captured from Sub0Squad runs | `test/golden.test.js` (the viewer), `test_golden_replay` (the library) | re-capture from a real run; review the diff |
| [replies/](replies/README.md) | recorded model-reply shapes, each with the files before and the required outcome | hand-written after real runs | `test_replies` | add a `.case` when a run shows a new shape |
| [scenarios/squad/](scenarios/README.md) | the mock squad's scenarios: whole attempts (replies, a gate, outcomes, identities) written by hand after the squad's T0 cases | hand-written ([docs/MOCK_SQUAD.md](../docs/MOCK_SQUAD.md)) | `test_consumer_contract` (outcomes, files, refusal texts, identities) | add a `.squad` file, then regenerate `mock/` |
| [mock/](mock/README.md) | the persisted attempt of each scenario, in the B0 format plus `mock-trace.json` | generated by `consumer/mock_squad` (`mock_squad <scenarios> <mock> --update`) | `test_consumer_contract` (byte-identical to a fresh run), `test/mock.test.js` (the viewer loads every attempt) | regenerate, review the diff by hand in the same commit |
| [mirror/](mirror/README.md) | the synthetic mirror: an invented project's forge state, truth and shape | generated by `tools/mirror/` ([docs/MIRROR.md](../docs/MIRROR.md)) | `test/mirror.test.js` (regeneration matches) | `npm run fixtures:mirror` |

The C++ tests receive their fixture directory as an argument from `CMakeLists.txt`; the node tests find theirs relative to `test/`.
